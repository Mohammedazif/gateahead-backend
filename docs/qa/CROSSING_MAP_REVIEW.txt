GateAhead crossing identification and grouping review — 16–17 November 2026

Scope: reproduce the Peelamedu/FCI and Payyanur screenshots, correct public
vehicle crossing eligibility, identify individual markers on hover, and group
parallel-track points in web/mobile lists without merging their predictions.
Three agents handled backend, web, and mobile; parent reviewed integration,
ran regression checks, and exercised the refreshed local API in Chromium.

Findings and fixes

- The reproduced FCI fixture contains 26 explicitly private crossing nodes.
  Access tags and directly connected roads now exclude those nodes. Public
  residential roads across railway spurs remain eligible; a nearby yard alone
  is never a reason to remove a public road crossing. Explicit vehicle bans
  and pedestrian-only connections are excluded from public vehicle results.
- Road topology now supplies optional group_id, group_name, and group_size.
  Groups stop at junctions, remain within 80 metres along the road, and cannot
  join two crossings on the same mapped rail way. Names/proximity alone do
  not establish a group. Four reproduced Payyanur track pairs form four groups.
- Existing stored OSM restrictions survive provider outages and restarts.
  Fresh positive evidence can restore an access-restricted record. Moderation
  rejections and unrelated user pins retain their previous status.
- Hover identifies the actual gate, road/area when available, distance, group
  membership, and individual timing/uncertainty. Labels use literal DOM text.
  Escape dismisses hover regardless of focus; theme changes do not duplicate it.
- Nearby and train lists group explicit road crossings, with expandable member
  checks. Original gate IDs, saved selections, per-track estimates, and dated
  train run identities remain separate. Missing checks are not invented.
- A browser test exposed a map loading race: an old empty-gate load callback
  could overwrite newer data. Delayed callbacks now use current state and
  remove stale listeners. The API-before-map-load scenario is reproducible.
- Mobile simulation exposed navigation overflow at 320px with 1.4x text.
  Tabs now wrap. Web member IDs and timing columns also wrap on phone screens.
